Proposed architecture

Source video → bounded decode → tracked people / objects → compact crop-state heads → temporal transitions → focused q30 verification → original-frame evidence

Retain periodic complete-video coverage, uncertainty fallback and existing candidate sources while measuring recall. This architecture requires qualified observations and a replacement state producer; simply enabling today’s additive specialists does not implement it.

Prioritized adoption plan

1. Replace repeated VLM state questions with tracked, learned scene states

Largest plausible coupled speed/consistency improvement; an experiment, not an established gain.

Adopt

CashGuard event-triggered query scheduling and DINOv2/CompVision SigLIP state heads.

What changes in Forte

Add a replacement observation producer: cheap people/object tracks → compact shared crop encoder → calibrated cash/safe/screen/presence states → temporal transitions. Invoke q30 for uncertainty and event verification; preserve periodic whole-video coverage and a union of proposal signals.

Current state: Our accepted run uses5745 Qwen calls/40clips (143.625 per clip). Full-frame plus up to4 region questions repeat at every state sample. Crops, factual prompts, rules and verification already exist; those are not new features to add.

Evidence required

Measure state recall, full-video verdicts, candidate recall, VLM call/token counts, latency and fallback rate. Keep at least current15/21 positives, all19 clean negatives and zero processing failures on regression; freeze a separate camera/setup evaluation for generalization.

2. Use dense local action windows and better event timestamps

Targets brief-event misses and localization while keeping broad scanning inexpensive.

Adopt

Event anchors from tracking, minimum durations, hysteresis and event-history guards.

What changes in Forte

Expand original-frame sampling near departures, client changes, object appearance/disappearance and uncertain hand/device activity. Keep action onset separate from the later time at which enough evidence confirms it. Recheck supported event intervals with the current verifier.

Current state: State sampling is capped at100 samples and at most1Hz. A142s clip therefore has a nominal spacing around1.42s. Verification then reduces a roughly8s window to10 sampled frames. The accepted confirmation change removed1 false alarm but nearest-event median error worsened1.0→1.5s and within2s hits12→11.

Evidence required

Review event type/start/end, actor, object and visibility on permitted material; one-to-one type/time matching. Maintain a uniform coverage floor; do not turn unobserved ID/device/counting actions into proof of omission.

3. Broaden domain-specific perception and complete procedural fact producers

Needed to address missing violation categories; public object training alone is insufficient.

Adopt

Hotel-style dedicated domain classes and persistent object tracks, trained against difficult normal examples.

What changes in Forte

Use authorized own/permitted data for keys in locks, cups/coats/bags, small ID versus notes, hand/device interactions, actor roles and transaction boundaries. Qualify object classes, then qualify each procedural type separately. Start with observable states and simple temporal logic before a new temporal transformer.

Current state: RF-DETR+ByteTrack, RTMPose, temporal checks and a transformer interface already exist, but are inactive/unqualified. The public RF candidate covers cards/notes, missed3/16 IDs and has6 banknote false positives. Crop2B primary macro score94.53125% failed its95% gate and did not test absence or procedural actions.

Evidence required

Camera/setup-grouped class and complete-video tests, hard negatives, event-level precision/recall and full visibility. New types require their own approved producer and release gate. Do not enable staged weights simply because they trained successfully.

4. Profile and test small existing scheduling optimizations

Lower implementation cost; likely smaller upside than replacing the state producer.

Adopt

Use existing parallel_layout first; test verify_concise separately after agreement checks. Measure batching and expensive detector cadence in a future replacement producer.

What changes in Forte

Record queue, decode, layout, state questions, verification, evidence, prefill/decode tokens and fallback counts for the accepted q30 pipeline. Test one flag at a time against frozen regression and identical hardware/network load. Detector inference should use a measured sampling/batching policy with dense windows when needed.

Current state: parallel_layout, verify_concise, job_priority and change_gating already exist, default off. Earlier staged-concise results belong to another architecture and do not establish a q30 gain. Prefix/multimodal caching and bounded admission already exist. Current summaries do not isolate exact state/verify or GPU-prefill percentages.

Evidence required

Identical verdicts, no lost true positives, validated timestamps/evidence, zero failures; compare direct and public API timings separately. Change gating needs brief-event recall tests; job priority changes completion order rather than total GPU work.

5. Test a smaller VLM only on the focused questions

Potential serving-cost/latency reduction after request sparsification; no automatic speedup from a smaller model name.

Adopt

Targeted4B door/screen verification, not an unrestricted whole-video violation search.

What changes in Forte

Benchmark a compact model on frozen crop/window tasks with ambiguous, absent-object and clean examples. Keep q30 fallback until complete-video and load results support promotion.

Current state: No compact candidate is qualified for our actual scene/verification tasks. The2B adapter’s oracle-box card-versus-note metric is a different task. Veriti’s larger reviewer harmed overall accuracy, illustrating why parameter count alone is a poor selection rule.

Evidence required

Task-level accuracy, uncertain rate, calibrated thresholds and full-video type/time/evidence results on the same hardware; count cascade fallback work and both models’ memory. Retain q30 unless quality and operational gates pass.

Concrete gaps before specialist activation

Specialists currently add work; they do not replace the VLM state producer.

The service processes native-frame specialist perception under one lock and then analyze() still runs the usual VLM states before specialist proposals. Enabling specialists alone can increase latency. A replacement producer and measured detector batching/cadence are required.

Service · Analyzer

Long-video sampling can conflict with specialist departure continuity.

The100-state cap makes long-video spacing exceed1s, while _state_departures requires adjacent supporting observations within specialist_max_gap_s=1.1 and a sustained absence interval. This can prevent support on a142s clip. Generate denser role observations or explicitly reconcile sampling with coverage; do not increase a gap allowance and claim missing frames were observed. This is a dormant-path issue, not an established explanation for the current six misses.

First experiments

  1. CPU/source-level sampling and producer-contract checks, then isolated parallel_layout agreement/latency trial.
  2. Train/calibrate narrow crop states on permitted camera-grouped data and evaluate as shadow proposals with q30 fallback.
  3. Replace repeated state requests only after state/event regression evidence; benchmark one request, four active jobs and six public uploads on the same host.
  4. Use separate reviewed type/time/camera tests for accuracy gains; target at least one additional valid positive without losing existing correct verdicts or adding false alarms.
  5. Evaluate compact focused VLM and deployment tuning only after request scheduling is efficient.

Keep these constraints

  • Keep current verification: it removed one observed false alarm.
  • No blind reduction of temporal sampling, global threshold relaxation, broad second-pass recall mode or activation of unqualified weights.
  • Do not translate crop AUC, object recall, test counts or all-positive F1 into bank-video accuracy.
  • The exposed40-video suite remains regression; a fresh camera/setup test is needed for generalization.
  • No estimated speed multiplier or under30s guarantee is established by this comparison.
