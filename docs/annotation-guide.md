# Локальная проверка разметки

Рабочий процесс реализован в `annotations/`. Он создает очередь по содержимому, сохраняет исходные слабые метки, предоставляет локальный интерфейс проверки и экспортирует только явно проверенные человеком записи с утвержденным разделением данных. Это инструмент подготовки данных; production inference не читает эту папку.

На 17 октября 2026 года по результату A02 подготовлены **40 уникальных единиц проверки из 42 записей**. Все 40 имеют состояние `pending`. Проверенных событий и подтвержденных отрицательных окон пока нет. Эти числа описывают готовность очереди, а не качество распознавания. Необходимы человек, работающий с локальным интерфейсом, и локальная проверка сценарных групп для блокировки split. Никакие исходные видео или метки не просматривались облачной моделью при разработке этого инструмента.

## Запуск

Из корня репозитория после установки общих зависимостей проекта:

```powershell
python -m annotations.cli seed --manifest data/manifests/recordings.jsonl --review-queue data/manifests/review_queue.jsonl --workbook-rows data/manifests/workbook_rows.jsonl --media-root .
python -m annotations.cli status
python -m annotations.cli serve --port 8765
```

Откройте `http://127.0.0.1:8765` вручную в локальном браузере. Не открывайте интерфейс с приватными материалами через облачный визуальный инструмент, не делайте облачные скриншоты и не публикуйте локальный сервер. Внешние API, CDN, шрифты, аналитика и внешние картинки отсутствуют. Сервер привязан к `127.0.0.1`, проверяет Host/Origin, использует случайный токен сессии и запрещает встраивание в чужую страницу. В консоли выводятся только агрегаты; тела записей и пути видео не логируются.

По умолчанию приватный SQLite-журнал находится в `annotations/private/review.sqlite3`; эта папка исключена из Git. На Windows храните ее в каталоге с ограниченными пользовательскими правами: POSIX `chmod` не создает полноценную Windows ACL. Нужные данные должны также исключаться из production image и runtime mounts согласно правилам A02/A17. Защита локального веб-сервера не заменяет контроль доступа к самому компьютеру.

Если браузер не открывает `.mov`, можно подготовить локальные беззвучные прокси:

```powershell
python -m annotations.cli proxy
```

Команда использует установленный `ffmpeg`, не меняет исходники и не выводит приватные диагностические строки. Прокси нужны только для навигации: для доказательств регистрируйте кадры из исходного декодера A05 с его реальными `pts_sec`. Звук не анализируется; при проксировании он полностью удаляется. Исходное видео в интерфейсе всегда воспроизводится без звука.

## Что проверять

1. Просмотрите весь уникальный клип и все потенциальные события, включая несколько разных эпизодов. Не ограничивайтесь исходной положительной меткой или указанной секундой.
2. Для каждого эпизода отметьте начало, конец и опорный кадр на исходной временной шкале. Время указывается в секундах от нормализованного начала исходного видео, не в номере кадра, не в PTS прокси и не по формуле `frame_index / fps`.
3. Укажите наблюдаемые признаки `present`, `absent` либо `unclear`. `absent` означает проверенное отсутствие в полном релевантном контексте; заслонение, выход за кадр и начало действия до записи требуют `unclear`.
4. Зарегистрируйте исходные кадры в `frames` с `frame_id`, локальным `path`, `pts_sec`, `width`, `height`. Ссылайтесь на их ID в фактах и `evidence_frame_ids`. Опорное время события должно точно совпадать с временем одного из 1–3 кадров доказательств.
5. Сохраните ограничения обзора в `visibility_regions` со значениями `clear`, `partial`, `unobservable`. Запишите нерешенные вопросы в `unresolved_items`; не превращайте их автоматически в отрицательный ответ.
6. Проверьте нормальные похожие действия и исключения. Нельзя устанавливать по изображению личность, полномочия, сумму по банковской системе, умысел или дисциплинарную вину. Факт перемещения наличных не доказывает хищение.
7. Если визуальное событие проверено, но норма либо ее применимость не подтверждена, используйте `rule_grounding_status: unresolved`, `rule_id: null` и `verdict: null`. Это допустимая частичная разметка для дальнейшей проверки, но не готовый бинарный эталон для оценки результата.
8. Для `verified_applicable` нужны существующее включенное правило A04, все точные состояния его признаков, `temporal_verified: true` и `exceptions_verified: true`. Программа проверяет архивный checksum каталога и соответствие ID правила типу события. Положительный `verdict: violation` требует хотя бы одного такого события.
9. Укажите локальный ID рецензента и завершите состояние `reviewed` только после человеческой проверки. Имя и распознавание лица не нужны. Локальная модель может готовить предложения, но не может самостоятельно установить `human_reviewed`.

Интерфейс позволяет редактировать JSON полей проверки и создавать **непроверенный** шаблон события с `unclear` и пустыми ссылками. Такой шаблон не пройдет финальную проверку, пока не будут внесены источник кадров, ненулевой интервал и подтвержденные признаки. Запись промежуточного состояния `in_progress` разрешена. При конфликте ревизий повторно загрузите запись, чтобы не затереть работу другого рецензента.

## Отрицательные окна

Неразмеченный фрагмент положительного видео не является отрицательным примером. Каждое отрицательное окно задается отдельно:

```json
{
  "start_sec": 0.0,
  "end_sec": 2.0,
  "negative_verified": true,
  "context_complete": true,
  "visibility": "clear",
  "criteria_version": "forte.taxonomy.v1"
}
```

Это исключительно синтетический пример формы, не метка какого-либо исходного видео. Признак отсутствия пересчета требует полного релевантного этапа, непрерывной видимости и всех путей ручного/машинного пересчета. Короткий фрагмент передачи не устанавливает, что пересчета не было ранее. Проверяйте исключения для упаковок по точному правилу A04.

Отрицательные окна не могут пересекать проверенные события. `verdict: no_violation` разрешен лишь при `full_review_complete: true`, пустых событиях и нерешенных вопросах и непрерывном объединенном покрытии всего видео явно подтвержденными отрицательными окнами. Частично проверенные отрицательные окна могут использоваться отдельно; они не дают отрицательного вердикта всему видео.

## Исправления, дубликаты и спорные метки

Содержимое `source_records`, хеш, запись и исходные пути неизменяемы через редактор. Исходные workbook-значения копируются локально при `seed --workbook-rows`; записи очереди A02 копируются через `--review-queue`. Разные имена одинакового содержимого имеют одну единицу проверки и полный список `recording_ids`.

Исходная неоднозначная временная метка и флаг расхождения остаются в исходных локальных записях. Не исправляйте их по предположению. После просмотра запишите в `corrections` исходное значение, исправленное значение, основание и ID рецензента. `needs_adjudication` предназначен для нерешенного расхождения; экспорт для обучения его исключает. SQLite-аудит сохраняет исходную и новую версии каждой правки с автором, временем и ревизией.

## Локальная модель-помощник

Допустим только явно локальный процесс внутри командного развертывания. Сохраняйте идентификатор checkpoint, revision, лицензию, параметры и ID локального запуска в `local_model_provenance`; результат остается предложением в `in_progress`. Не используйте внешнюю мультимодальную модель, облачный coding assistant, публичную загрузку видео или сервис расшифровки. После просмотра человеком укажите `review_origin: human`; происхождение локального предложения остается в журнале.

Пайплайн сохраняет приватный `analysis.private.json` формата `forte.local-proposal.v1`, включая незавершенные и неуспешные попытки. Его можно импортировать без просмотра содержимого в облачном coding assistant:

```powershell
python -m annotations.cli import-proposal --input C:\PRIVATE\work\JOB\attempt-1\analysis.private.json --proposal-root C:\PRIVATE\work --source-root C:\PRIVATE\uploads --frame-root C:\PRIVATE\work
```

Пути выше — вымышленные примеры. Укажите реальные абсолютные командные каталоги; каждый флаг root можно повторять. Не используйте корень диска вместо конкретного каталога. `--sample-id` позволяет дополнительно указать ожидаемый непрозрачный ID, `--expected-revision` — защититься от изменения записи после пакетного планирования. Формат аудита: `asset: VideoAsset`, `frames: [FrameRef]`, `decisions: [FactDecision]`, `candidate_events: [CandidateEvent]`, `verified_events: [VerifiedEvent]`, `window_decisions`, `provenance`, `coverage`, `phase`, `error_code`. В каждом окне сохраняются `clip_id`, исходный интервал, `frame_ids`, `facts`, `candidate_events`, `generation`, `complete` и `disposition`.

Импортер заново считает SHA-256 исходного видео и связывает его ровно с одной уже созданной единицей проверки. Проверяются разрешенные каталоги, исходный job ID, временная шкала, фактический JPEG/размеры/checksum кадров, допустимые признаки/типы и принадлежность фактов точному набору кадров каждого окна. Относительные ссылки, подмена исходника, чужие кадры и jury test media отклоняются. Значения `model_revision: null`, `processor_version: null` либо отсутствие подтвержденной serving-attestation сохраняются как неизвестные — загрузка ревизии не выдумывается.

Результат попадает в отдельный неизменяемый список `local_model_proposals`; повторный импорт одних байтов является no-op. Запись получает `in_progress` и `review_origin: local_model`. Импорт не меняет события человека, отрицательные окна, verdict, полноту проверки, split lock или разрешение обучения. Если человек уже сохранял свою работу, импорт отклоняется; конфликт ревизии также не затирает правки. Raw-предложения не включаются в экспорт проверенных обучающих/оценочных данных.

В локальном интерфейсе предложения показаны отдельно с исходными кадрами, наблюдениями по окнам и честным статусом незавершенного анализа. Кнопка копирования создает только **несохраненный черновик**: применимость нормы остается `unresolved`, проверки последовательности/исключений — `false`, verdict — `null`. Человек должен проверить и исправить каждое утверждение, затем отдельно сохранить свое решение. Отсутствие предложений модели не является отрицательной меткой. Новая версия интерфейса требует перезапуска старого процесса сервера; делайте это лишь после завершения текущего редактирования, чтобы не потерять несохраненный текст.

## Разделение и экспорт

После локальной проверки сценарных групп A02/A10 создают утвержденный split manifest. Нужны `locked: true`, `scenario_review_complete: true` либо эквивалентное явное `scenario_groups_reviewed: true`, непустой `approved_by`; train требует `training_authorized: true`. Противоречащие флаги проверки отклоняются. Рабочие разделы — `train`, `validation`, `final_check`; старый `test` принимается для совместимости с исходным контрактом A01. Команда не признает candidate split окончательным:

```powershell
python -m annotations.cli sync-splits --manifest data/splits/locked_split.json
python -m annotations.cli export --output reviewed.jsonl
python -m annotations.cli export --output reviewed-train.jsonl --split train
```

Имя `locked_split.json` — пример будущего утвержденного файла. Пока он отсутствует, команда синхронизации и последующий экспорт проверенных данных остаются заблокированными. Все исходные записи должны присутствовать в lock; один scenario group и один хеш не могут пересекать split. Импорт lock сохраняет его SHA-256 в каждой экспортируемой записи.

Экспорт всегда остается внутри `annotations/private/`, выполняется через атомарную замену и включает только `human_reviewed` с `reviewer_id`, `reviewed_at` и проверенным split. Jury test media исключаются и не могут стать обучающей разметкой. Экспорт не выдает исходные слабые метки или пути исходных видео; локальные ссылки кадров остаются приватными. Формат: `annotations/schema.v1.json`, контекстная проверка: `annotations.store.validate_annotation`. A09 формирует окна только из явных событий и отрицательных окон; A10 принимает целый клип для бинарной оценки только при разрешенном `verdict`. Каталог фактов не должен импортировать приватные записи в production.

Для приватной пакетной правки поддерживается `python -m annotations.cli apply --input annotations/private/patch.json`; форма объекта: `sample_id`, `expected_revision`, `patch`. Команда не выводит содержимое.

## Проверки реализации

Запуск синтетических проверок без pytest из корня репозитория:

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
python -m unittest annotations.test_workflow annotations.test_proposals -v
```

43 проверки прошли в проектном `.venv` через `python -m pytest annotations/test_workflow.py annotations/test_proposals.py -q`. Они проверяют границы исходных времен/кадров, явное отрицательное покрытие, точные включенные правила A04 и отклонение выдуманного ID нормы, неизменность источников, конфликт ревизий, аудит, дубликаты, split lock, `final_check`, исключение jury media, локальную изоляцию сервера и HTTP Range. Проверены также импорт незавершенного локального предложения, изоляция человеческих правок, исключение raw-предложений из обучающего экспорта, контроль исходных хешей/путей/кадров/окон и защищенный просмотр JPEG. Интеграционный тест создает синтетическое видео, намеренно вызывает отказ искусственного локального provider и импортирует настоящий audit пайплайна без превращения отказа в отрицательный результат. Без полных зависимостей/ffprobe этот интеграционный тест явно пропускается. Эти проверки не измеряют распознавание реальных клипов или качество модели.
