# Интерфейс проверки видео: спецификация A19 → A16

Язык интерфейса — русский. Назначение — быстрая проверка наблюдений человеком. Основа бренда подтверждена [официальным веб-брендбуком](https://forte.kz/en/logo); композиция и семантические цвета ниже выбраны командой.

## Подключение

`brand/tokens.json` содержит объект `tokens`, версия схемы `1.0`. В каждом токене указаны значение, роль, происхождение, источник, дата и ограничения. `brand/theme.css` экспортирует 35 переменных `--forte-*` и локальный `@font-face`. A16 может импортировать CSS через сборщик или скопировать его и шрифт с лицензией в свои статические ресурсы. При копировании сохранить относительный путь шрифта и файл OFL. Никаких внешних CDN, удаленных шрифтов или банковской аналитики в рабочей странице.

Базовая типографика: Open Sans 400, `16px/1.5`; заголовок страницы 28–40px/600–700; секции 20px/600; пояснения и время 14px. Для таймкодов использовать `font-variant-numeric: tabular-nums`. Не сжимать длинные русские заголовки правил в одну строку. Разрешить перенос URL и идентификаторов.

## Рабочая композиция

Максимальная ширина 1440px, внешние поля 24–32px на большом экране и 16px на узком. Шаги отступов: 4, 8, 12, 16, 24, 32, 48px. Фон `--forte-page`, панели белые, радиус панели 20px и контролов 12px. Границы `#D5D5D5` подходят для декоративных разделителей; для обязательной видимой границы поля использовать `--forte-control-border`.

Шапка: обычный текст «Forte / Проверка видео», рядом компактная подпись «Прототип для дататона». Главный заголовок описывает задачу. Не имитировать интернет-банк и не использовать изображения карт, баннеры или денежные показатели.

При результате большая область видео занимает примерно две трети рабочей ширины; список событий и пояснения расположены рядом. Это ориентир, не жесткая пропорция. Ниже 900px панели идут последовательно: результат, видео, события, объяснение и правило. Важные кнопки остаются видимыми при ширине 360px и увеличении текста. В интерфейсе нет обязательного меню, истории или аккаунтов.

## Состояния и формулировки

| Состояние | Текст | Отображение и поведение |
|---|---|---|
| До выбора | «Загрузите видео для проверки» | Доступный выбор файла и необязательное перетаскивание. Подпись «Видео MOV. Проверка выполняется в сервисе команды». Лимит файла показывать из фактической конфигурации. |
| Файл выбран | «Файл выбран» | Видимы имя, размер и действие «Начать проверку». Тип и ошибки проверяются до запроса, сервер остается окончательной проверкой. |
| Загрузка | «Загружаем видео» | Блокировать повторный POST. Процент допустим только при измеренном прогрессе передачи. |
| Обработка | «Проверяем видео» | Реальный статус задания и прошедшее время. Не выдумывать процент, очередь, этап или обещанное время; общий polling-статус достаточен, если API не дает этапы. |
| `no_violation` | «Признаки нарушений не обнаружены» | Спокойный зеленый статус с иконкой/текстом. Исходное видео доступно. Это формулировка о наблюдаемом материале, не гарантия соблюдения всех правил. |
| `violation` | «Обнаружены возможные признаки нарушений» | Янтарный статус, число событий, отдельная карточка для каждого. Не называть человека нарушителем и не заявлять установленную вину. |
| Ограниченная видимость | «Есть ограничения видимости» | Дополнительная серая метка и конкретное ограничение, только если оно получено от сервера. Это не третий вердикт jury API. |
| Ошибка обработки | «Не удалось обработать видео» | Красный статус технической ошибки, идентификатор задания, безопасное пояснение, доступное повторное действие. Ошибка никогда не отображается как нормальный результат. |
| Потеря связи | «Не удалось получить статус» | Сохранить job_id и предыдущие данные; предложить повторить запрос. Ошибка сети сама по себе не доказывает сбой задания. |

Нельзя заполнять недостающие ограничения, правило или события выдуманным текстом. Если отдельного метаданного нет, показать это явно. Состояния читаются текстом, а не только цветом.

## Событие и доказательство

Карточка содержит тип из утвержденной таксономии, таймкод, краткое наблюдение и ссылку на правило. События упорядочены по времени; выбор не объединяет разные события. Таймкод — настоящая кнопка «Перейти к …», которая управляет исходным видео; десятичная точность не должна теряться в данных. Пример отображения: `00:44.2`.

Показать 1–3 оригинальных JPEG на событие в полном соотношении сторон: `width:100%; height:auto; object-fit:contain`. Темный нейтральный фон вокруг кадра допустим. Не применять `object-fit:cover`, принудительный квадрат, цветокоррекцию, декоративные рамки поверх изображения или скрытые обрезания. Каждый кадр имеет время из метаданных и доступное увеличение. Если изображение не загрузилось, показать честное сообщение, не пустой «успешный» контейнер.

Наблюдение и нормативное основание — отдельные читаемые блоки. В правиле видны название, пункт при наличии, источник и ограничение применимости при наличии. Ссылка открывает проверяемый первоисточник. Нельзя повышать неполную ссылку до «проверенного пункта» либо представлять политику другого банка как политику Forte. Не показывать неоткалиброванный score как «вероятность нарушения».

## Действия и доступность

Основная кнопка: белый текст на `#A31551`, нормальное начертание 600, высота не меньше 44px. Hover можно затемнить до `#4A0221`; фокус — видимый контур 3px с отступом 3px. Вторичные действия — белая поверхность, читаемый текст и видимая граница. Состояние disabled имеет явный текст/атрибут и не заменяет сообщение о причине. Ссылки в пояснениях подчеркнуты.

У поля файла есть связанный label; область перетаскивания не заменяет клавиатурный выбор. Tab достигает всех действий; Enter/Space активируют кнопки; модальное увеличение кадра закрывается Escape и возвращает фокус. Статус обработки объявляется через `aria-live="polite"`; не озвучивать каждую секунду. Ошибки связываются с контролом. Уважать `prefers-reduced-motion`.

Команда приняла [контраст 4.5:1 для обычного текста и 3:1 для крупного](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html); [значимые границы и фокус проверяются отдельно](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html). В статической проверке белый текст/маджента дает 7.545:1, основной текст/белый 16.858:1, вторичный текст/белый 7.057:1. Coral и Sky не использовать как цвет мелкого текста на белом. Эти расчеты не заменяют проверку собранного интерфейса.

## Приемка с A16

Проверять только синтетические данные и кадры, обозначенные как демонстрационные. Нужны состояния: загрузка, настоящее ожидание ответа в контролируемом mock-сервере, normal, positive, несколько событий, ограничения видимости, failed, неверный формат, недоступный backend, узкая ширина, клавиатурный фокус и увеличение кадра. Mock-сценарии не должны включаться в production. Обнаруженные замечания и реальные результаты фиксируются в `docs/visual-qa.md`.
