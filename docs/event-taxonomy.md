# Таксономия визуальных признаков v1

Машиночитаемый публичный каталог: `annotations/taxonomy.v1.json`. Он содержит 21 общий признак и 4 типа кандидатов. Это определения для разметки и композиции решений; проверенные события исходных видео в каталоге отсутствуют. Статус: `generic_observable_candidates_awaiting_dataset_review`.

Импорт: `annotations.catalog.load_taxonomy()`, `fact_definitions()` и `event_definitions()`. Простое чтение JSON не требует зависимостей. Рецензирование использует A01 `FactDecision` и `FrameRef` из `forte.shared.schemas`. Описания конкретных норм, применимости и исключений принадлежат A04 в `rules/catalog.json`.

| Стабильный ID события | Русское название | Граница вывода |
|---|---|---|
| `CASH_UNATTENDED` | Возможное оставление наличных без наблюдаемого контроля | Уход должен быть наблюдаемым, а применимость конкретной процедуры — подтвержденной. Заслонение человека не доказывает уход. |
| `CASH_TRANSFER_WITHOUT_OBSERVED_COUNT` | Передача наличных без наблюдаемого пересчета | Положительное утверждение об отсутствии действия возможно только при полном контексте и наблюдении всех путей пересчета; исключения упаковок проверяются по правилу. |
| `CASH_MOVED_TO_PERSONAL_STORAGE` | Возможное помещение наличных в личную зону хранения | Непрерывная траектория и назначение места должны быть подтверждены. Карман одежды и сумка — разные условия; умысел и владелец не устанавливаются. |
| `WORKSPACE_ACCESS_BY_OTHER_PERSON` | Вход другого человека в рабочую зону | Фиксируется геометрическое пересечение проверенной границы. Право доступа по кадрам не устанавливается; автоматическое правовое обоснование отключено до появления допустимого основания. |

ID сохраняются при уточнении русского текста. Расширение каталога требует согласования A03/A04/A08/A11 и новой версии при изменении семантики. Неизвестный ID не допускается в финальную разметку; отправьте его на разбор и оставьте наблюдение неопределенным.

## Признаки

| Группа | Стабильные ID |
|---|---|
| Объект и поверхность | `CASH_VISIBLE`, `CASH_ON_WORK_SURFACE` |
| Контроль и движение | `CASH_HANDLER_PRESENT`, `CASH_HANDLER_LEAVES_WORKSTATION`, `CASH_HANDOVER_VISIBLE` |
| Видимость и полнота | `WORK_AREA_CONTINUOUSLY_VISIBLE`, `PROCEDURE_CONTEXT_COMPLETE`, `ALL_COUNTING_PATHS_VISIBLE` |
| Пересчет | `CASH_COUNT_VISIBLE`, `LOOSE_BANKNOTES_RECEIVED`, `LOOSE_BANKNOTES_ISSUED` |
| Контекст операции | `BANK_CASH_WORKSTATION`, `CASH_RECEIPT_OPERATION`, `CASH_ISSUE_OPERATION`, `CUSTOMER_SERVICE_CONTINUES` |
| Предыдущий прием и хранение | `PREVIOUSLY_ACCEPTED_CASH_TRACKED`, `PREVIOUS_RECEIPT_COMPLETE`, `CASH_PLACED_IN_PERSONAL_CONTAINER`, `CASH_PLACED_IN_CLOTHING_POCKET` |
| Граница зоны | `OTHER_PERSON_ENTERS_WORKSPACE`, `WORKSPACE_BOUNDARY_VISIBLE` |

У каждого признака есть `question_ru`, `definition_ru`, `absence_requires_ru` и готовые фразы по состояниям: `observable_phrase_ru`, `absence_phrase_ru`, `unclear_phrase_ru`. Для фактического описания используйте фразу соответствующего состояния, никогда свободные модельные заметки и никогда положительную фразу при `absent`. Каталог A04 имеет собственные более узкие формулировки конкретного правила; для итогового правового описания приоритет у них.

`present` означает подтвержденное присутствие признака; `absent` — подтвержденное отсутствие в явно проверенном полном контексте; `unclear` — недостаточную видимость либо контекст. Не переводите `unclear` в `absent`. В частности, отсутствие наблюдаемого пересчета в коротком фрагменте не означает отсутствие пересчета в операции.

## Машинные условия

Каждый элемент `event_types` содержит:

- `event_type_id`, `name_ru`, `definition_ru`;
- `required_fact_states`: обязательные состояния признаков базового визуального кандидата;
- `is_omission` и `required_context_fact_ids`: машинные признаки пропуска действия и полноты контекста;
- `temporal_requirements`: описание последовательности, требующей локальной проверки;
- `normal_lookalikes_ru`: нормальные похожие действия;
- `grounding_status`: честный статус правовой применимости категории;
- `rule_specific_fact_ids`: подсказки дополнительных признаков; это не логическое AND и не замена точным ветвлениям A04.

У типа передачи без пересчета `is_omission: true`, а `PROCEDURE_CONTEXT_COMPLETE` и `WORK_AREA_CONTINUOUSLY_VISIBLE` обязательны в состоянии `present`. Для применимого правила пересчета дополнительно нужны `ALL_COUNTING_PATHS_VISIBLE` и признаки конкретного приема/выдачи по A04. Базовое совпадение таксономии дает только кандидата. Автоматический итог допускается лишь по включенной верифицированной норме с точными условиями и исключениями.

## Разметка и пропуски

У события есть интервал `[start_sec, end_sec]`, опорный исходный кадр, 1–3 ID доказательств, проверенные факты, статус правового обоснования и ограничения. Все времена относятся к нормализованной шкале исходного видео. Несколько разных событий сохраняются отдельно. Перекрывающиеся кандидаты сами по себе не подтверждают одно или несколько нарушений; итоговая агрегация принадлежит A11.

Нормальные похожие действия и явно проверенные отрицательные окна размечаются отдельно. Неразмеченное время положительного клипа, невидимая зона и неопределенный тип операции не являются отрицательной разметкой. Обозначайте неясные наблюдения, пропуски обзора, нерешенное обоснование и спорные исходные timestamps в локальном журнале, сохраняя исходные значения.
