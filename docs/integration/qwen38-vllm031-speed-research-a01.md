# Qwen3.8 native vLLM 0.31 speed research (A01)

Read-only audit, 2026-10-17. This audit ran no GPU work, model imports, model requests, private-content reads, service changes, or speculative configuration changes. The current full-19 behavior, frame coverage, generation seed 4096 and deadlines remain the control.

**Decision:** no cheap speculative mode is verified lossless for this exact hybrid GDN + multimodal + LoRA + JSON workload. CPU/GPU n-gram implementations and grammar integration exist, but an unresolved upstream hybrid-state correctness report prevents promoting them on API support alone. The most concrete GDN opportunity is checking why the existing fused CUDA decode operator is unavailable or disabled; A100 supports the architecture, while a CUDA 12.x build may omit the operator. A separate correctness and latency gate is required for any candidate.

### Why lossless promotion is blocked

Official upstream [issue 39273](https://github.com/vllm-project/vllm/issues/39273) remains open in the fresh GitHub API snapshot. Reports include Qwen3.8-27B, malformed structured output and healthy acceptance rates despite corruption. The related [PR 40738](https://github.com/vllm-project/vllm/pull/40738) is open and unmerged. The frozen GDN metadata resets accepted-token metadata on non-spec steps and lacks the PR's `spec_decode_src_indices` recovery field. Its Mamba postprocessing also lacks the backward-copy guard discussed in later issue comments. These observations support an unresolved risk; they do not prove the private workload currently reproduces it. No patch was applied.

The [official losslessness explanation](https://docs.vllm.ai/en/v0.31.0/features/speculative_decoding/) describes algorithmic distribution preservation subject to floating-point effects. That is different from fixed-seed byte-identical output across a changed execution/sampling path. Keep rejection sampling `standard`; synthetic acceptance settings are not an eligible correctness-preserving shortcut. Raising lookup length to 8 is not proof of repaired hybrid state.

## A100 GDN backend: exact useful limits

1. **Prefill:** the resolver enables FlashInfer for SM90, or supported SM10/SM12 cases with CUDA 13 and head dimension 128. CuteDSL is restricted to supported newer architectures. A100 SM80 resolves to Triton even when an unsupported prefill backend is requested. Switching the prefill name cannot activate an A100 FlashInfer/CuteDSL GDN kernel. [Resolver](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/mamba/gdn/qwen_gdn_linear_attn.py#L93).
2. **Packed Triton decode:** `VLLM_ENABLE_FLA_PACKED_RECURRENT_DECODE` defaults to `1`. It applies to decode-only, non-spec batches. Explicitly setting an already-enabled default is not an optimization. Verify the recorded setting before proposing a change. [Environment default](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/envs.py#L1224), [dispatch](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/mamba/gdn/qwen_gdn_linear_attn.py#L1273).
3. **Fused CUDA decode:** `VLLM_GDN_DECODE_KERNEL` defaults to `cuda`. The guard permits SM80+, non-interleaved Qwen layout, K/V dimensions 128, SiLU/sigmoid gating, BF16 model and convolution state, BF16 or FP32 recurrent state, and an actually built `torch.ops._C.fused_gdn_decode_post_conv_mtp`. Missing support silently falls back when the default is implicit; explicitly requesting `cuda` raises rather than manufacturing support. [Exact guard](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/mamba/gdn/qwen_gdn_linear_attn.py#L509).
4. **Build restriction:** v0.31's CMake populates `FUSED_GDN_DECODE_ARCHS` only with CUDA compiler **13.0+**. The list includes SM80. Thus the Python SM80 guard does not imply the current CUDA 12.9 image contains the operator. Confirm the image build/symbol receipt or recorded fallback reason before any restart. A different CUDA 13 build is a separate runtime candidate, not a launch-only flag. [Frozen CMake](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/CMakeLists.txt#L1105).
5. **Precision:** changing SSM cache from FP32 to BF16 or using quantized KV changes numerical behavior. Neither is categorized here as a lossless speed knob. The generic `mamba_backend` selector concerns selective-state-update implementations and should not be substituted for GDN's own resolver.

The compiled CUDA kernel uses fast-math, so even a supported fused decode candidate needs exact-output/semantic checks against the current control. Fused configuration alone does not establish a speed gain.

## Separate gate, if root schedules one

First resolve the recorded Triton fallback without touching the running model. If fused CUDA is already built and only explicitly disabled, the smallest candidate changes that single selector while preserving cache dtypes and all other model, adapter, processor, template and generation identities. Otherwise a CUDA 13 runtime build is required. Do not change prefill/backend, batching, speculation and precision together.

Any later n-gram experiment should be isolated, unselected and budgeted separately. A conservative **candidate only** is `{"method":"ngram_gpu","num_speculative_tokens":2,"prompt_lookup_min":8,"prompt_lookup_max":12,"rejection_sample_method":"standard"}`. These values reduce draft depth and incidental short matches; they do not fix the upstream state issue. This audit does not authorize or execute that experiment.

Compare the frozen full-19 request at the same original frame coverage/PTS, JSON schema, adapter, seed 4096, sampling settings, limits and deadlines. Preserve raw output and token IDs when available; check exact parsed fields, evidence/timestamps, no missing stages, no truncation, and content validity—not merely JSON syntax or acceptance rate. Include fresh-engine and repeated-engine runs plus prefill/decode boundary cases; upstream reports indicate request history and state-block boundaries matter. Measure end-to-end median/tail and accepted/drafted tokens separately. A pass on a tiny prompt or a healthy acceptance counter is insufficient to promote this exact hybrid workload.
