# Modern video specialists: 17 October 2026 addendum

The first practical pilot is **TimeLens2-2B**, followed by TimeLens2-4B for interval quality and VideoChat3-4B for motion/streaming reasoning. These are actual July 2026 checkpoints. This order supersedes the older VideoMAEv2 proposal, which is on hold. The running Qwen teacher and W1 stay unchanged. All rows are research candidates; no candidate weights were downloaded or executed when this document was frozen. Any later local staging has a separate proof.

TimeLens2 is the closest match for finding *when* a described cash-handling action occurs. Its official inference profile uses 2fps and a 480×480 pixel ceiling, and produces a JSON interval array. That output needs a new grounder contract, native source PTS binding, bounded intervals and explicit uncertainty; it cannot be dropped into the existing fact/event schema. Standard Qwen3-VL architecture support is verified at the family level, while the exact checkpoint/profile has not run in the current vLLM service. The 2B weights are about 4.88GB, but model storage does not establish the activation/KV budget or latency. [Official 2B card](https://huggingface.co/MCG-NJU/TimeLens2-2B), [paper](https://arxiv.org/abs/2607.17423).

VideoChat3 is a stronger second comparison for fine motion and streaming responses. Its compressed visual representation may trade away tiny cash/object details, so the published generic motion and long-video results need a task-level comparison. The custom implementation and streaming control tokens require a reviewed isolated runner. [Pinned official release notes](https://github.com/MCG-NJU/VideoChat3/blob/015f52eb2ea70b5abda30192aee18034f2c5f13b/README.md), [project performance table](https://mcg-nju.github.io/VideoChat3/).

CamVLM is the most directly surveillance-tuned modern lead, but its access flow has not been accepted. Its active PTZ policy cannot create unseen pixels in existing fixed-camera recordings, and generic anomaly classes do not prove Kazakhstan bank-rule coverage. Cosmos3-Edge is a compact physical reasoner rather than a trained cash-compliance detector; use reasoner-only evaluation and exclude external API examples from private workflows. [CamVLM paper](https://arxiv.org/abs/2609.06475), [official Cosmos3-Edge release](https://huggingface.co/blog/nvidia/cosmos3edge).

The 15 October Bolt release is fresh, but freshness and a 24GB file size do not resolve the documented A100/runtime contradiction. Its native video ceiling is two minutes, so longer sources need explicit windows. Keep it as a generic teacher comparison after compatible execution is established, not a reason to interrupt the existing teacher. [Official release](https://blogs.nvidia.com/blog/nemotron-3-5-super-vl/), [model/runtime card](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-24GB).

V-JEPA 2.1 is a real **16 March 2026** temporal encoder option, not an answer-generating anomaly model. The official ViT-B/384 encoder is 80M parameters but its linked `.pt` file is **1,664,223,428 bytes**; HEAD length and multipart ETag are metadata, not a computed SHA-256. Source is MIT with named Apache utility exceptions; a separate explicit license statement for the linked CDN weights was not established, so do not infer it from code alone. Default K64/384/patch16/tubelet2 yields 18,432 dense contextual tokens. Reducing temporal length creates a new measured profile, and pooled temporal bins still see the whole window. No checkpoint/container inspection or unrestricted pickle load was performed. [Pinned release/checkpoint table](https://github.com/facebookresearch/vjepa2/blob/204698b45b3712590f06245fbfba32d3be539812/README.md), [source license](https://github.com/facebookresearch/vjepa2/blob/204698b45b3712590f06245fbfba32d3be539812/LICENSE).

InternVideo3-8B is an actual June 2026 long-video autoregressive agent with **18,728,678,544 bytes** of weights and custom code; it is not evidence of fast small-encoder throughput. InternVideo-Next is a **December 2025** release despite CVPR2026 acceptance. No official public Cosmos-Embed2 checkpoint was verified. [InternVideo3 checkpoint](https://huggingface.co/yanziang/InternVideo3-8B-Instruct), [InternVideo-Next paper](https://arxiv.org/abs/2512.01342).

X was searched for the releases. No directly readable relevant release post was verified; inaccessible NVIDIA announcement leads are recorded without treating them as evidence. The September ReactVAU X lead points to a real paper/repository, but the repository uses a noncommercial source license and no fine-tuned checkpoint link was verified. Primary cards, pinned repositories and papers support the shortlist. Exact revisions and per-file weight hashes are in `configs/serving/specialist-candidates-2026-addendum.json`.

Evaluate against the **machine-experiment frozen 28/6/6 train/validation/final partition**, whose human-lock flags remain false. Human-reviewed fact/event gold is unavailable; current provided binary/time labels allow coarse diagnostics only. This does not require manual work from the user before a bounded experimental comparison. Bank-rule accuracy, normal-video false positives, source-bound brief actions, and end-to-end p50/p95 latency all remain unmeasured for these candidates. No generic benchmark can justify a 100% bank-accuracy claim.
